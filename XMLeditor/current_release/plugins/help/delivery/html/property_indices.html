Property_indices

Links to the property entries in the prior input traces. If any layer property  in the
model_description  section varies_areally, it must have a corresponding entry in this
section. In principle, just about any property can vary on a trace-by-trace
basis. In practice, only a few of these variations probably really matter,
and these are what must go into the prior traces. You will want
links for time_link, probably depth_link, and possibly net_to_gross_link. Kriged
constraints on thickness might come in through the thickness_link.
Known wet areas could have probabiliity_of_oil=0 etc to simplify the
inversion.

The prior traces have a set of blocks for varying properties. the last block is
always time. The number here must be the block number for the property in question.
the inverter can ignore bad values (-999.0) in the input traces.

There are are large list of possible links here in the schema. Many are very unlikely to be
needed. Not all are implemented, but
the important ones probably are.

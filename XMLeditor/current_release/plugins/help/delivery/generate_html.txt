html/seismic_data.html
Stack data
Information about the stacks(s):
Up to 2 stacks are allowed (use 2 if significant AVO effects possible).
Each stack must have sane entries for the <hr width="100%" size="2"> 
<b>stackname</b>: SU big--endian file containing the stack (may be a named pipe)<br>
<b>minimum offset </b>(length units consistent with velocities e.g. ft, or m)<br>
<b>maximum offset </b>(length units consistent with velocities e.g. ft or m)<br>
<b>reflector time </b>to salient reflecor in model (milliseconds)<br>
<b>stack velicity </b>(ft/second, or m/s)<hr width="100%" size="2">
<b>Wavelet information</b> is also needed:the <b>wavelet filename</b>: a big--endian SU file with one trace: the wavelet. Requisite header fields set correctly (ns,dt,f1)<br>
<b>Signal to noise</b>. This is actually the <i>estimated noise RMS amplitude</i>
<hr width="100%" size="2">
<b>AVO_terms</b>. <br>
These are coefficients in the reflectivity model (see the tech. paper). <br>
Usually A,B=1 and these are fixed (sigma_A=sigma_B=0, which is assumed if
there are no sigma_A/sigma_B entries). A,B, can be used to compensate for
amplitude errors in the wavelet if it's too small etc, but the wavelet extraction
ought really to have got this right
